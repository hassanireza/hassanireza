## <img src="./assets/svg/index-05.svg" height="26" alt="05"/>&nbsp;&nbsp;Brand &amp; Art Direction

<div align="center">
<img src="./assets/svg/divider.svg" width="100%" height="1" alt=""/>
</div>

<br/>

Every project I ship carries a written brand system before a single line of interface code, defining palette, typography, tone, and the rules that keep a visual identity disciplined instead of decorative. The direction below governs **Abyssal Liturgy**, a ceremonial identity built for the edge of land and sea, where fashion, ritual, and biological form are treated as forgotten religious painting, submerged for centuries.

<div align="center">

<img src="./assets/svg/palette-banner.svg" width="100%" alt="Abyssal Liturgy palette: Void #050506, Charcoal #111318, Cold Slate #2b3038, Ash Gray #6d727b, Bone White #e9e4da, Bio Residue #3c4b46. Ninety-five percent black, one light source."/>

</div>

<br/>

**Governing rule:** ninety-five percent black, one light source, texture over color as the primary signal.

<br/><br/>

<img src="./assets/svg/mark-woodland.svg" width="40" height="40" alt=""/>

### [Woodland Chess](https://woodlandchess.github.io/)
<sub>Mobile-first chess app | Stockfish in WebAssembly, Lichess integration, live demo</sub>

</div>

A chess application built on the same premise as everything above: restraint is a design choice, not an absence of one. Woodland Chess has three modes that share one visual language, and it inherits the Abyssal Liturgy system directly, with near-black surfaces, Cormorant Garamond italics, one 24px icon family and a 2px radius. Every colour, spacing value and easing curve lives as a CSS custom property.

<table>
<tr><td width="36" valign="top"><img src="./assets/svg/icons/cpu.svg" width="20" height="20" align="absmiddle" alt=""/></td><td valign="top"><b>Computer.</b> Stockfish 18 Lite running locally as WebAssembly</td></tr>
<tr><td width="36" valign="top"><img src="./assets/svg/icons/globe.svg" width="20" height="20" align="absmiddle" alt=""/></td><td valign="top"><b>Online.</b> Live games through the Lichess Board API</td></tr>
<tr><td width="36" valign="top"><img src="./assets/svg/icons/puzzle.svg" width="20" height="20" align="absmiddle" alt=""/></td><td valign="top"><b>Puzzles.</b> Rated tactics from the Lichess puzzle database</td></tr>
</table>

<div align="center">
<img src="./assets/svg/woodland-architecture.svg" width="100%" alt="Woodland Chess architecture: a shared UI layer feeds three independent modes, Computer, Online and Puzzles, each backed by its own services and external dependency"/>
</div>

<br/>

The front end is a strict-TypeScript React SPA served from Vite, with History API routing and no router dependency. There is no backend of our own: Computer mode makes no network calls beyond loading fonts, online play uses OAuth with PKCE straight from the browser, and puzzles read the public Lichess API. A thin shared layer (menu frame, mode navigation, design tokens) sits under three independent modes: `chess.js` and a Stockfish UCI client for Computer, an NDJSON stream reader for Online, and a state-machine puzzle engine with scoring, streaks and achievements. CI tests, builds and deploys to GitHub Pages on every push.
